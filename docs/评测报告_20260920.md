## 5. RAG 检索离线指标（26 用例，裸检索口径）

**口径（重要）**：直接调用 `KnowledgeBase.search`（Chroma 内置 embedding 向量检索），**不含**生产链路的查询改写与 LLM 重排（`search_with_rewrite`），因此该数字是检索能力的**下限**而非线上表现。知识库仅 28 条种子（5 类别 × 5 病害 + 3 用药安全），规模小，指标仅反映当前种子库 + 内置英文 embedding 的组合水平。

| 指标 | 结果 |
| --- | --- |
| Recall@5（23 条可答用例，Top-5 命中任一期望 source_id） | **0.2609（6/23）** |
| Top-1 source_id 命中率 | **0.0435（1/23）** |
| 对抗用例（3 条域外查询）top-1 相似度 | 番茄晚疫病 0.607（误命中 KB-HL-004，存在误引风险）/ 市场价格 0.111 / 葡萄霜霉病 0.006 |

解读（不美化）：内置 all-MiniLM-L6-v2 为英文向量模型，对中文农业术语区分度弱（霜霉/白粉/蔓枯的"症状识别"条目互相串扰），这是本轮评测暴露的**真实短板**；生产链路靠"查询改写 + LLM 重排 + Agent 侧引用约束 + 检索不到明示"兜底。改进方向：换中文 embedding 模型、启用 pgvector 检索（`cucumber-ai/app/services/retriever.py` 已在后续规划）、扩充知识库规模。

## 8. 局限说明

1. **Judge 自评偏差**：Judge 与被测 Agent 同为 deepseek-chat，存在同模型自评偏差；六维分数只代表该 Judge 口径下的相对水平，建议定期人工标注校准（evaluator docstring 已明示）。
2. **RAG 口径为下限**：Recall@5/Top-1 为裸检索（无改写/重排），不代表 `/search` 与对话链路的线上表现；知识库仅 28 条种子，结论不可外推到大库。
3. **对话用例规模**：Judge 覆盖 22 条对话（29 个评分点），意图指标覆盖全部 108 条；未对 108 条逐条做 Judge（成本考虑），对话子集按意图均衡抽样。
4. **模型变更**：本轮用 deepseek-chat（09-14 记录中的 deepseek-flash 在端点上不可用）；跨模型分数不可直接比较。
5. 评测在本机单机运行，未经过 8002 服务 HTTP 层（脚本直调 evaluator，orchestrator/KB 为同一进程真实组件）。
