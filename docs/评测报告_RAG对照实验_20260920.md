# RAG 检索改进对照实验报告（2026-09-20）

> 评测驱动的检索改进实验：同一冻结评测集、同一知识库，四版检索配置对照。
> 所有数字均为本机真实运行输出，原始 JSON/Markdown 摘要在 `docs/rag_retrieval_*_20260920.*`。
> 本报告只新增产物，不改写任何既有文件。

## 0. 冻结基线与口径（引用既有文件，原文不动）

基线来自 2026-09-20 全量评测（`docs/评测报告_20260920.md` §5，原始数据 `docs/eval_run_20260920.json`）：

- 知识库：`cucumber-agent/echomind/data/cucumber_knowledge.json`，28 条黄瓜病害知识（KB-XXX-NNN）
- 检索：嵌入式 ChromaDB，默认 embedding = Chroma 内置 ONNX all-MiniLM-L6-v2（英文模型）
- 评测集：`echomind/evaluation/eval_cases.json`（version 2026-09-20）RAG 用例 **26 条**
- **基线指标：Recall@5 = 0.2609（6/23），Top-1 source_id 命中率 = 0.0435（1/23）**

**分母口径说明（不是数据问题）**：26 条 RAG 用例 = 23 条可答用例（带期望 source_id，进分母）
+ 3 条域外对抗用例（番茄晚疫病/市场行情/葡萄霜霉病，期望为空，**不进分母**，
用于观察检索器对域外查询的置信度表现）。因此"26 用例只有 23 进分母"是设计口径。

本次实验额外口径：

- **期望答案全程未改**：四版跑的是同一份 `eval_cases.json`，未为凑指标修改任何标注。
- **数据隔离**：评测用独立持久化目录 `echomind/data/chroma_eval/` + 独立 collection
  `kb_eval_v1..v4`，BGE 版全部向量在新 collection 重建，运行时 `data/chroma` 旧数据不覆盖。
- **别名表设计在先、评测在后**：V3/V4 的病害别名（流胶病/蔓割病→蔓枯病、跑马干→霜霉病、
  白毛病→白粉病）均为真实农学俗称，设计时只看病害学不看评测结果；held-out 集验证不过拟合。

## 1. 实验配置与运行方式

| 版本 | 配置 |
| --- | --- |
| V1 | 基线：Chroma 内置 all-MiniLM-L6-v2（英文），裸向量检索 |
| V2 | 换 **BAAI/bge-small-zh-v1.5** 中文向量（cosine 空间），新 collection 重建全部向量 |
| V3 | V2 + 查询侧别名归一化（病害俗称→学名、口语→知识类目，追加到查询文本再向量化） |
| V4 | V3 + 关键词混合检索：向量 Top15 与关键词命中（KB 编号 +0.60 / 病害学名 +0.25 / 类目词 +0.10）取并集，按"向量分+确定性加成"重排，不引入 reranker 模型 |

复现命令（在 `cucumber-agent/echomind/` 目录）：

```bash
PYTHONUTF8=1 ../.venv/Scripts/python -m evaluation.run_retrieval --version v1   # v2/v3/v4 同理
PYTHONUTF8=1 ../.venv/Scripts/python -m evaluation.run_retrieval --version v4 --held-out
PYTHONUTF8=1 ../.venv/Scripts/python -m evaluation.run_retrieval --download-model  # 仅预下载 BGE 权重
```

每次运行自动记录：git commit、embedding 模型、用例文件与版本、用例总数、有效分母，
输出 `docs/rag_retrieval_<version>[_heldout]_20260920.json`（逐条明细）+ 同名 `.md`（摘要）。

**依赖与网络纪实（如实记录）**：本机到 PyPI/阿里云镜像链路当天仅 15–33 KB/s，
`sentence-transformers`（含 scikit-learn/scipy）多次超时未装成功；最终方案：
torch 2.8.0+**cpu**（pytorch 官方 CPU 索引，约 2 分钟装完）+ `transformers 4.45.2` 最小依赖集；
BGE 权重经 **ModelScope CDN 直连**（实测约 11 MB/s）下载至
`echomind/data/models/bge-small-zh-v1.5/`。推理为 BertModel + CLS pooling + L2 归一化，
与 bge-zh-v1.5 官方用法及 SentenceTransformer 加载该权重等价；代码保留
sentence-transformers 优先、transformers 兜底的双后端（`knowledge_base.load_bge_embedding_fn`）。

## 2. 四版指标对照表（dev 冻结集，分母 23）

| 指标 | V1 基线 | V2 中文向量 | V3 +别名归一 | V4 +关键词混合 |
| --- | --- | --- | --- | --- |
| Recall@1 | 0.0435 | 0.3478 | 0.3043 | **0.8261** |
| Recall@3 | 0.1304 | 0.6087 | 0.6087 | **0.9130** |
| Recall@5 | 0.2609 | 0.7391 | 0.6957 | **0.9565** |
| MRR | 0.1080 | 0.4891 | 0.4326 | **0.8783** |
| Top-1 source_id 命中率 | 0.0435 | 0.3478 | 0.3043 | **0.8261** |
| 平均查询延迟 | 14.3–14.7 ms | 7.4 ms | 8.3 ms | 8.3 ms |
| 冷启动（含 28 条种子首次向量化） | 1.10 s | 2.50 s | 2.43 s | 2.36 s |
| 模型磁盘体积 | 166.4 MB（ONNX 缓存） | 91.9 MB | 91.9 MB | 91.9 MB |
| 内存 RSS 增量（粗估） | 9.7 MB（复跑口径*） | 410 MB | 412 MB | 413 MB |
| 安全类子集（n=6）Recall@5 | 0.1667 | 0.8333 | 0.6667 | 0.8333 |
| 安全类子集 Top-1 | 0.0000 | 0.6667 | 0.5000 | 0.6667 |
| 域外对抗 Top-1 平均置信度 | 0.2414 | 0.5727 | 0.5881 | 0.7029 |

\* V1 首跑时 psutil 未装（记为 None），表中为复跑补测；V1 复跑核心指标与首跑完全一致
（R@5=0.2609、Top-1=0.0435），与冻结基线逐位吻合，说明评测可复现。
冷启动复跑口径（向量已持久化）：V1=0.19 s、V4=2.06 s。

**阶段目标核对**：Recall@5 ≥ 0.80 ✅（0.9565，22/23）；Top-1 ≥ 0.60 ✅（0.8261，19/23）；
跨病害混淆下降 ✅（基线 Top-5 大量串到无关病害/健康叶片条目，V4 仅剩 1 例霜霉↔白粉症状混淆）；
安全类（用药注意/禁限用/间隔期）不退化 ✅（子集 Recall@5 0.1667→0.8333，Top-1 0→0.6667，见 §5）。

**V3 退化的如实说明**：纯向量口径下，V3（别名归一化追加词）相比 V2 各项指标**不升反降**
（R@5 0.7391→0.6957，Top-1 0.3478→0.3043）——追加的学名/类目词摊薄了原始提问的语义重心。
别名信息真正产生收益是在 V4：同一份别名匹配结果不作为文本拼接，而是作为**确定性重排加成**
（+0.25/+0.10）作用于候选集，才带来 R@1 0.35→0.83 的跳升。这也是"V3→V4"而非
"V2 直接加关键词"的对照设计价值：加成所需的病害/类目匹配与归一化共用同一别名表。

**域外对抗置信度上升的说明**：V4 对域外查询（如"葡萄霜霉病的症状"）Top-1 置信 0.70 高于
V2 的 0.57，原因是"霜霉病"别名命中给了黄瓜霜霉病条目 +0.25 加成——检索层如实返回了
最接近的库内条目（跨作物同名病害），这属于检索器的正常行为；域外拦截应在应用层
（意图识别/答案校验）处理，不计入本次检索指标。

## 3. Held-out 防过拟合验证（只在最终版 V4 跑一次）

用例集：`echomind/evaluation/eval_cases_heldout.json`（split=held_out，**23 条**），
逐条同义改写自 23 条可答用例（口语化/换句式/引入俗称如"流胶"），期望 source_id 原样继承。
**held-out 不参与任何调参决策**：四版对照、别名表、加成权重全部只基于 dev 集确定后，
才对 V4 跑这一次。

| 指标 | V4 dev（冻结集） | V4 held-out（同义改写） | 差值 |
| --- | --- | --- | --- |
| Recall@1 | 0.8261 | 0.7826 | -0.043 |
| Recall@3 | 0.9130 | 0.9130 | 0 |
| Recall@5 | 0.9565 | 0.9565 | 0 |
| MRR | 0.8783 | 0.8565 | -0.022 |
| Top-1 source_id 命中率 | 0.8261 | 0.7826 | -0.043 |
| 安全类子集（n=6）Recall@5 | 0.8333 | 0.8333 | 0 |

两套指标几乎重合（R@5 完全一致，Top-1 差 1 条用例），说明 V4 的提升来自
"中文向量 + 确定性规则"的通用能力，而非对 dev 集表述的过拟合。
原始输出：`docs/rag_retrieval_v4_heldout_20260920.json/.md`。

## 4. 失败案例分析（最终版 V4 仍失败的用例）

dev + held-out 合计 46 条可答用例中，V4 未进 Top-5 的 2 条、进了 Top-5 但未中 Top-1 的 7 条，
分类如下（每类附真实例子；明细见两份 JSON 的 `details`）：

### 4.1 类目混淆（主要失败模式，5 例）——同一病害下"化学防治/用药注意/农业防治/发病条件"串位

- dev「白粉病化学防治方案」期望 KB-PM-004，实际 Top-1 为 KB-PM-005（用药注意）——
  两者标题都含"防治/用药"语义，向量分接近时确定性加成（病害 +0.25 两者相同）无法拉开。
- dev「农药安全间隔期通用规范」期望 KB-SAFE-001，仅列第 5——查询不含具体病害名，
  病害加成缺失，四个病害的"用药注意"条目（均含间隔期表述）凭向量分占据前四。
- held-out「白粉病一般在什么样的环境下容易发生」期望 KB-PM-002（发病条件），仅列第 5——
  "发生/环境"未进入类目别名表的强信号位，被同病害的症状/防治条目压过。

### 4.2 短查询区分度不足（2 例，dev/held-out 同一条目）

- dev「炭疽病用药注意」/ held-out「炭疽病用药方面有哪些讲究」期望 KB-ANT-005，
  **两集均未进 Top-5**——查询极短，向量分低（<0.35 的关键词加成天花板），
  Top-1 均为 KB-ANT-004（化学防治）。"用药注意"类目加成（+0.10）不足以补偿向量差距。
  这是 V4 在 46 条中仅有的 2 条 Recall@5 失手，也是后续最优先修复点
  （方向：类目命中时对同类目条目做二次向量重排，或标题字段加权）。

### 4.3 跨病害混淆（1 例）

- held-out「黄瓜叶子上出现白色粉末状的东西是什么毛病」期望 KB-PM-001（白粉病症状），
  Top-1 为 KB-DM-001（霜霉病症状，其内容含"白色→灰紫色霉层"演进描述）——
  口语化症状描述未显式出现病害名，别名机制无从触发，纯向量被霜霉病条目截获。
  相比基线（同类混淆占失败主体）已降至个例。

### 4.4 别名缺失 / 知识缺口（0 例）

- 别名机制经受了 held-out 显式考验：「黄瓜茎蔓开裂、流胶是怎么回事」经"流胶→蔓枯病"
  归一化后 Top-1 命中 KB-GST-001（得分 0.9067）；未发现因别名缺失导致的失败。
- 全部期望 source_id 均存在于 28 条知识库中，无知识缺口型失败；真正需要扩充知识库的是
  域外对抗类（番茄/葡萄病害），属于应用层拒答范畴而非检索失败。

## 5. 安全类用例专项核对（用药注意/禁限用/间隔期，n=6）

口径：期望命中 KB-SAFE-001/002/003 或各病害 -005（用药注意与抗性管理）条目的用例。

| 版本 | 安全子集 Recall@5 | 安全子集 Top-1 |
| --- | --- | --- |
| V1 基线 | 0.1667（1/6） | 0.0000 |
| V4 最终版 | 0.8333（5/6） | 0.6667（4/6） |
| V4 held-out | 0.8333（5/6） | 0.5000（3/6） |

安全类**无退化且大幅提升**；唯一 Recall@5 失手即 §4.2 的「炭疽病用药注意」
（KB-ANT-005），已列入后续修复点。禁限用（KB-SAFE-002）与轮换原则（KB-SAFE-003）
在两集均稳定 Top-1。

## 6. 最终决策：切换运行时配置到 V4

**结论：V4 明显优于基线（R@5 0.2609→0.9565、Top-1 0.0435→0.8261，held-out 复现），
已切换 cucumber-agent 运行时检索配置。** 落地方式（接口不变）：

- `echomind/mcp/knowledge_base.py`：
  - 新增模块级别名表 `DISEASE_ALIASES` / `CATEGORY_ALIASES` 与
    `normalize_query()` / `hybrid_rerank()` / `load_bge_embedding_fn()`；
  - `KnowledgeBase.__init__` 新增可选参数 `embedding_model / alias_norm / hybrid /
    collection_name`（显式参数 > 环境变量 `KB_EMBEDDING_MODEL / KB_ALIAS_NORM / KB_HYBRID` > 缺省）；
  - **缺省**：本地 BGE 权重与后端就绪（`_bge_available()`）时启用 V4 全套，
    否则自动回退 V1 基线行为（无新依赖的环境行为与旧版完全一致）；
  - BGE 使用独立 collection `knowledge_base_bge_zh`（cosine 空间），旧 collection 数据不动；
  - `search(query, top_k)` 签名与返回结构不变，MCP handler、orchestrator 调用方零改动。
- 模型权重（95.8 MB）在 `echomind/data/models/bge-small-zh-v1.5/`（gitignore 不入库，
  部署时经 `--download-model` 或 ModelScope 拉取）。
- 验证：`pytest echomind/tests` 13 项全绿（切换后复跑 3.48s）；端到端冒烟
  「黄瓜茎蔓开裂流胶是怎么回事」Top-1 = KB-GST-001（0.9067）。

### 资源代价（如实记录）

- 内存：RSS 增量约 +410 MB（torch+transformers+模型常驻），基线 ONNX 约 +10 MB；
  对 8GB+ 部署机可接受，边缘小内存设备可经 `KB_EMBEDDING_MODEL=default` 回退。
- 冷启动 1.1s→2.4s（含模型加载与 28 条种子向量化）；查询延迟 14.3ms→8.3ms（不升反降，
  bge-small 仅 4 层，且 V4 走的是已持久化索引）。
- 磁盘：模型 91.9 MB，小于基线 ONNX 缓存（166.4 MB）。

## 8. 遗留项

1. 「炭疽病用药注意」类短查询 Recall@5 失手（§4.2）：建议类目命中时对同类目条目二次向量
   重排，或索引时把 title 作为独立字段加权入库。
2. V3 纯向量口径退化提示：别名信息不适合做文本拼接，后续若引入 LLM 查询改写，
   应以"结构化约束（病害/类目槽位）"而非"拼接关键词"的方式注入。
3. 域外拦截（番茄/葡萄等跨作物同名病害）需在应用层补规则，检索层不兜底。
4. 本机 PyPI 链路极慢导致 sentence-transformers 未装上；当前 transformers 等价后端已够用，
   若后续环境网络正常可 `pip install sentence-transformers` 无缝切到首选后端（代码已兼容）。
